# 问题采集链路（决策记录）

> 状态：**方向已定，优先级暂低**（先让板子跑通显示/音频/触摸，再做这条链路）
> 决策日期：2026-11-02

---

## 一、决策

孩子提问时，设备**采集语音**，走下面这条链路：

```
孩子按住说话
   ↓
设备采集（I2S 数字麦，1.85 板载）
   ↓  （家里局域网）            （外面玩的，先存 SD，回家自动同步）
家里的 server.py  ←───────────┘
   ↓
ASR 转文字
   ↓
LLM 出答案初稿（已有的 QUESTION_PROMPT）
   ↓
家长审核（改文字 / 试听语音 / 驳回）
   ↓
生成语音（同一个"小豆豆"音色）
   ↓
下发设备 → 播放
```

**和之前"录音不上传"的关系**：红线改了，但不是放弃隐私——
**音频只到家里那台电脑，不到任何第三方云。** 这改变了红线的表述，不是拆掉了它。

---

## 二、为什么是"上传到家里"，不是"上传到云"

用户的直觉是对的：**不识别就没有复述，没有复述就没有"被听见"**。
但"识别"不一定需要云端。

| 环节 | 云端方案 | 家里方案（推荐） | 差别 |
|---|---|---|---|
| ASR | Whisper API / 阿里一句话识别 | **whisper.cpp 跑在家里 Mac** | 音频不出家门；M 系列芯片转 10 秒语音约 1 秒 |
| LLM | 必需（可选 DeepSeek/通义） | 同左（**只发文字，不发音频**） | 云端只看到"为什么树叶会变黄"这句话，与现在的 `ask_ai()` 一致 |
| TTS | 云 TTS 按次计费 | **`say -v Tingting`（服务器就是 Mac）** | 零成本、零延迟、音色和预录语音完全一致 |

**关键结论**：

> **音频不出家门；文字可以出（因为文字就是孩子的问题本身，和现在家长手打的一样）。**

这条链路下，隐私暴露面比"家长把问题打进去"只多了一样东西：**孩子的原声**。
而那份原声**只存在家里那台电脑上**，可以设保留期、可以一键删。

## 三、隐私护栏（做这条链路的前提）

| # | 护栏 | 说明 |
|---|---|---|
| 1 | **默认关** | 出厂 `USE_MIC 0`；家长在页面上显式打开才采集 |
| 2 | **不常开麦** | 只在"按住说话"期间采集（3–10 秒），松手就停；不做常听/唤醒词（第一期） |
| 3 | **音频只存家里** | 存 `voice-in/`，不进 git、不进备份云 |
| 4 | **7 天自动删** | 转完文字、家长审核完，音频按天数自动清理（默认 7 天） |
| 5 | **一键清空** | 家长页有"删除所有孩子录音"按钮 |
| 6 | **可听可核** | 家长审核页能回放原声，确认 ASR 没听错 |
| 7 | **敏感内容拦截** | 命中敏感词（死亡/暴力/陌生人…）时，不直接给孩子，强制走家长 |

## 四、几个关键设计选择

### 1. 采集方式：按住说话（对讲机式）

5 岁半对"按住说话"完全熟悉（微信语音）。**按下开始、松手结束、上限 10 秒**，比"点一下开始再点一下停"更可靠。

按下时：屏幕出现一个**录音波形/大圆点**（不需要中文）+ 一声提示音；松手：播"我听听……"（预录 0066）。

### 2. 什么地方能录

| 场景 | 处理 |
|---|---|
| 在家（局域网） | 直接上传，几秒钟出结果 |
| 在外面没网 | **存到 SD 卡**，回家后自动同步（复用现有的离线队列机制） |
| 一直没网 | 缓存最多 20 条，循环覆盖最老的；家长页可见"还有 3 条待上传" |

### 3. 答案怎么"说"出来

现在的设备只能播 SD 卡上固定编号的 mp3（DFPlayer 限制）。动态答案有两条路：

| 方案 | 1.85 板 | DevKitC |
|---|---|---|
| **流式播放服务器生成的 mp3** | ✅ `audio.connecttohost("http://server:8099/api/answer.mp3?id=12")` | ❌ 做不到 |
| 下载到 SD 再播 | ✅ 可行但慢 | ✅ 可行（DFPlayer 只认 SD） |

**所以"动态播报答案"是 1.85 专属能力**——这正好跟你买这块板子的理由一致。

### 4. 家长审核的是"音频"，不是"文字"

这是最容易被忽略的一点：文字审核完，交给 `say` 生成语音，**音色语速是固定的，但断句可能怪**。
所以审核页要能**试听**，觉得别扭可以改标点重生成。**听到的才是孩子听到的。**

## 五、失败模式

| 情况 | 设备表现 | 家长页表现 |
|---|---|---|
| ASR 没听清 | 播"我没听清，再说一次好不好？"（0067） | 显示低置信度标记 |
| LLM 没配置/超时 | 不播答案，改播"我记下来了"（0065） | 提示"手动写答案" |
| 家长驳回 | 设备不播，安静 | 显示驳回原因 |
| 内容敏感 | 设备不播 | 强制家长介入 |
| 家里服务器没开 | 排队，下次同步 | 显示积压数 |

**原则：设备永远不在"没有审核过的内容"上出声。**

## 六、为什么优先级低

这条链路要动的面很大：

1. 固件：I2S 录音 + WAV 封装 + 上传 + SD 缓存（约 300 行）
2. 服务端：接收音频 + ASR 调用 + 审核页试听 + `say` 生成 + 音频下发接口（约 250 行）
3. 依赖：whisper.cpp（或 API）、ffmpeg、`say`（仅 macOS）
4. 家长流程：多一步"试听审核"

**而它服务的场景（孩子提问）一周可能只有 3–5 次。**
相比之下，**先把屏、触摸、语音、图标跑通**，价值大得多。

## 七、分阶段实施（等硬件跑通后）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0** | 按住说话 → 存 SD → 回家同步 → 家长页能**回放原声** | 能听到孩子刚才说的话 |
| **P1** | 接入 ASR（家里 whisper.cpp）→ 文字进问题罐 | ASR 文字基本可用，家长能改 |
| **P2** | 审核通过 → `say` 生成 → 设备 `connecttohost` 播放 | 孩子听到"小豆豆"用自己的声音回答 |
| **P3** | 置信度、敏感词、保留期自动清理 | 护栏齐全 |

**P0 就能验证最关键的一件事**：孩子在设备上"按住说话"这件事，他愿不愿意做、做得顺不顺。
如果 P0 他就不爱按，后面全都不用做。

---

## 八、一句话

> **采集合规的关键不是"传不传"，是"传到哪、留多久、谁能删"。**
> 音频到家里那台电脑，文字才出门——这条链路既满足"被听见"，又不把孩子的声音交给第三方。
