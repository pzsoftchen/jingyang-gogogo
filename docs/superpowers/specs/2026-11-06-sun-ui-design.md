# 小豆豆的一天 · UI 重设计

> 状态：设计草案，已按 2026-11-06 决策更新，待批准
> 日期：2026-11-06
> 范围：设备端主界面、问题卡/字卡视觉、一天四幕与夜间模式。
> 不在本设计内：家长页改版、新内容模块、订阅/积分/排名。

---

## 一、为什么做

当前主界面是深蓝黑底 + 暖黄表情。它在床头不刺眼，但对 5 岁半的孩子更像"一块夜间工具"，不像一个愿意靠近的朋友。孩子第一眼看到的应该是**一个活着的小豆豆**，而不是一块显示进度的屏。

这次不改产品主线，只改"舞台"：

- 白天温和、明亮、有生命感
- 夜晚安静、变暗，不刺眼
- 同一个角色贯穿一天，而不是四张不同的壁纸
- 不增加内容、货币、排名或新的每日动作

---

## 二、用户与场景

- **孩子**：5 岁半，不识字，靠图形、表情、声音理解。
- **家长**：在手机家长页配置，偶尔看状态；不希望每天多一个操作。
- **设备**：1.85C 圆屏 360×360（另支持 DevKitC 240×240），ESP32-S3，本地语音包，服务器渲染中文卡片。

孩子感知到的目标不是"习惯养成"，而是：

> 一块会为他高兴的小屏幕，和一个住在里面的朋友。

---

## 三、目标 / 非目标 / 反目标

### 目标

1. 让第一眼更温暖、更像"我的东西"，而不是深色仪表盘。
2. 用一天四幕建立时间秩序：太阳出来 = 新的一天，月亮出来 = 该睡了。
3. 保留现有信息层级：顶部本周、中心角色、底部习惯。
4. 让问题卡/字卡与主界面属于同一个世界。
5. 夜间不刺眼，断网也能维持最后一次时段。

### 非目标

- 不做积分、连续天数、排行榜、兑换。
- 不做订阅、开放聊天、摄像头/麦克风。
- 不做四季/节日主题、天气内容、每日随机皮肤。
- 不改家长页的深色工具风格（只增加必要的配置项）。
- 不把中文常驻到设备屏幕上（设备端没有中文字库）。
- 不做全屏视频或高频粒子动画。

### 反目标（技术上成立也算失败）

- 孩子开始盯着屏幕看动画，而不是去做事。
- 屏幕变得太亮，影响睡前。
- 家长需要每天配置主题/穿衣。
- 为了视觉新增每日内容推送或新的进度货币。
- 两个板型（240/360）只有一块好看。

---

## 四、已确认的设计决定

以下来自与产品负责人的视觉讨论，作为本设计的基线：

1. 角色：**A · 光芒就是手**。太阳的 8 条光芒承担姿势，不再另画手臂/腿，避免两套线条打架。
2. 布局：**等比缩小版**。保留顶部、角色、底部三层信息，整体缩小到约 82%，四周留白。
3. 顶部：**7 个点沿圆屏排成缓弧**（不是直线）。
4. 顶部颜色：**B · 薄荷**。完成 = 薄荷 `#5BC8B0`；今天 = 珊瑚 `#FF8A65` + 外圈；未来 = 暖灰空心 `#B9C7C2`。
5. 底部：**也排成弧线**，与顶部呼应；两件习惯时靠拢到约 ±16°，不再拉得很开。
6. 卡片：**只保留一种暖纸风格**，不再做黑底/深蓝两套；夜间靠设备整体压暗。
7. 本期范围：**只做 Phase 1**（主界面 + 卡片 + 周点 + 家长页设备状态/音量）；穿衣和名字推迟到 Phase 2。
8. 1.85C 触摸：**直接点**。轻点某个习惯贴纸完成那一件；轻点小豆豆记录问题/留言；不再需要“选中环”。
9. 周点口径：**按当前启用的习惯数**判断过去每天是否完成；不做每日习惯快照。

## 五、视觉系统

### 5.1 一天四幕

| 时段 | 默认时间 | 背景 | 小豆豆 | 顶部 7 点 | 目标亮度 |
|---|---|---|---|---|---|
| 起床 / 出门 | 06:30–08:30 | 奶油 → 蜜桃，太阳升起 | 伸懒腰、眨眼 | 本周小太阳，今天更大 | 80% |
| 白天 | 08:30–17:00 | 浅天蓝 → 近白，云 | 安静眨眼 | 同上 | 100% |
| 傍晚 | 17:00–20:00 | 橙 → 丁香晚霞 | 挥手/开心 | 同上 | 70% |
| 睡前 / 夜 | 20:00–06:30 | 深蓝 → 靛蓝，月亮/星星 | 打哈欠、闭眼、睡帽 | 同位置，夜间配色 | 15–25% |

规则：

- 布局、角色位置、信息层级**不变**；只变颜色、光线和角色姿势。
- 时段边界默认取上面四个时间；先不做家长可调，避免新增配置负担。
- 进入新时段时角色做一次短动作（伸懒腰/挥手/打哈欠），**不做整点突变**。
- 夜间保留一个很小的暖色光源，不做纯黑。

### 5.2 角色：光芒就是手

- 一个圆圆的暖色太阳，8 条圆头光芒，右侧一条可弯曲成"挥手"。
- 不画独立手臂/腿；光芒承担姿势，轮廓干净。
- 面部：深棕眼睛、奶油高光、腮红、微笑；表情沿用现有 8 种（常态/开心/困/说话/惊讶/眨眼/睡/好奇）。
- 早晨光芒向上伸展；白天自然展开；傍晚右侧光芒卷起挥手；夜间光芒收短、变暗，可戴睡帽。
- 表情颜色必须在背景上可见：使用深棕五官 + 亮色脸部，不再使用深灰 `C_INK` 画在深色背景上。

### 5.3 布局与安全区

- 以 360×360 为基准，内容整体约 82% 缩放；有效内容控制在大约 300px 直径内。
- 三层：
  1. 顶部：7 个周点，沿半径约 150 的缓弧，跨度约 ±48°。
  2. 中心：小豆豆，太阳本体约 128px 直径（缩放后约 105px），光芒外缘约 180px。
  3. 底部：习惯贴纸，沿半径约 140 的下弧排列。
- 底部排列规则：
  - 1 件：正下方居中；
  - 2 件：±16°（已确认，间距约 77px）；
  - 3 件：约 −28° / 0° / +28°；
  - 4 件：约 −42° / −14° / +14° / +42°，图标可缩到 22–24px 半径，避免挤。
- 触摸模型（仅 1.85C）：
  - 轻点某个习惯贴纸 = 直接完成那一件；
  - 轻点小豆豆 = 记录一个问题；全部完成后 = 给爸妈留言；
  - 长按主界面 = 立即同步（家长便利，不要求孩子使用）；
  - 卡片模式：轻点翻页，长按退出；
  - 不再需要“选中环”；每张贴纸都是独立命中区。
- 状态：
  - 已完成：贴纸右上角小星星；
  - 未完成：正常贴纸；
  - 点已完成的贴纸 → “已经做过啦”，不扣分；
  - **没有红叉、没有失败画面、没有扣分**。
- 习惯图标沿用现有 emoji 位图；底色从深色圆改为奶油贴纸圆。若图标位图带深色底，需要重新生成透明/奶油底版本。

### 5.4 顶部 7 点 = 周一到周日

- 7 个位置固定对应周一到周日，最左边周一，最右边周日。
- 今天：更大 + 珊瑚填充 + 外圈；完成：薄荷填充；未来：暖灰空心。
- 今天全部完成时：保持珊瑚外圈和“今天”尺寸，填充改为薄荷，并加一个小星星/勾；既表示完成，也不丢失“今天”身份。
- 夜晚：未来点改为暗蓝灰 `#6B7A9E`；完成/今天保持薄荷/珊瑚，外圈用奶油色。
- 不写"周一/周二"文字；孩子看位置，家长在家长页看文字。
- 口径（已选）：按**当前启用的习惯数**判断每一天是否完成。已知副作用：家长中途加习惯后，过去已经完成的日子可能变灰；这和无失败画面的原则有张力。本期接受这个取舍；如果以后变成实际问题，再升级为“按当天习惯快照”的真实历史。
- 语义变化：现有 `WEEK=` 是"最近 7 天"，新界面用"本周一到周日"。协议上**新增** `WEEK_CAL=`（7 个 0/1，周一到周日）和 `WEEKDAY=`（1–7），保留 `WEEK=` 供旧固件；新固件只读新字段（见第八节）。

### 5.6 卡片：暖纸一种风格

问题卡和字卡都使用同一套暖纸视觉，不再区分日间/夜间版本：

- 背景：`#FFF8EC`；正文：`#3E3228`；次要文字：`#A38B72`。
- 问题/标题：珊瑚 `#E76F51`；分区标签（答案/反问/一起做）：薄荷深色 `#2F6F63`；提示语：`#2F6F63`。
- 大字（识字卡）：珊瑚 `#E76F51`，保持大而清晰；词语用 `#A38B72`。
- 页码点：薄荷填充 + 暖灰空心；角落可放一个很小的太阳标记 `#FFC93C`。
- 内容、字号层级、页数、三段结构**不变**；只换配色和轻微圆角/标记。
- 夜间不做深蓝卡片；设备整体压暗后仍使用暖纸卡。若实际测试发现夜间太亮/太难读，再单独评估夜间卡，不预先做两套。

### 5.7 动效

- 平时：每 4–6 秒眨眼一次；不做常驻漂浮/旋转。
- 触摸：立即"叮" + 角色表情变化 + 被触摸贴纸轻弹。
- 完成一项：贴纸上的小星星飞向顶部对应周点，角色开心；1 秒内完成。
- 全部完成：撒 1–2 秒星星/emoji 雨（沿用现有 4 种随机图案，改成新配色）；只触发一次。
- 时段切换：角色做一次短动作（伸懒腰/挥手/打哈欠），背景在约 2 秒内柔和换色；不做整点闪屏。
- 夜间：动画减半，避免睡前兴奋。

### 5.8 夜间与亮度

- 20:00 后进入夜间配色；背光目标 15–25%（默认 20%）。
- 1.85C 的 `LCD_BL` 是 GPIO5，需验证 PWM 调光；DevKitC 的 `TFT_BL` 同理。
- 若 PWM 不可用：至少使用夜间深色配色，不要把白底/亮黄留在床上。
- 冷启动无网络/无时间：先进入**夜间深色 + 20% 亮度**，直到 NTP 成功后再切到当前时段；不沿用可能过亮的旧时段，避免晚上开机刺眼。
- 断网运行中：沿用最后一次时段；恢复网络后按 NTP 重新计算，平滑过渡。
- RTC 未启用前，断网跨天可能无法准确切换；记录为已知限制，后续接 RTC。

## 六、名字、周几、幼儿园穿衣

### 6.1 名字

**本期（Phase 1）不做；推迟到 Phase 2。默认建议：不常驻屏幕。**

- 设备端没有中文字库，常驻名字需要服务器出图或烧死位图，占用 360 圆屏空间；5 岁半也不一定读。
- 归属感通过以下方式表达：
  - 早安/晚安语音里由家长录一句"景阳，早上好"（或固定语音）；
  - 家长页显示孩子名字；
  - 角色本身叫"小豆豆"，是"他的"。
- 若以后家里有两个孩子，再升级为"切换孩子档案"，属于独立功能，不在本次范围。
- 待确认：是否要一句带名字的固定/家长录音；若要，作为语音包新增一条，不改 UI。

### 6.2 周几

- 顶部 7 个点就是周一到周日；今天更大、珊瑚色。
- 不在设备上写"周一"；家长页显示"今天周一"。
- 这样孩子建立"位置—时间"的秩序，家长得到明确的周几信息。

### 6.3 幼儿园穿衣提示（已决定推迟到 Phase 2）

机制（不改现有推送预算）：

1. 家长页新增一张 **7 天穿衣表**：周一到周日，各选一个图标（园服/运动服/便服/自定义）+ 一句语音（可从固定语音包选，或家长录）。
2. 服务端把今天的穿衣语音**插入"出门流程"的 `rtSeq`**（现有协议已有该字段），设备在早上流程按分钟播放；不新增每日推送，不改协议结构。
3. 屏幕上可选：让小豆豆举起今天的衣服图标（👕/👟/🧥），不显示中文；家长页显示完整文字。
4. 临时换衣服：家长页一键改"今天"，不必改整周。
5. 语音必须来自家长选择/录制，不能由 LLM 即兴生成。

这条服务"每天做到"，不新增货币、不新增每日动作、不靠催；通过现有准入六问。建议作为 **Phase 2**，不与主 UI 重设计捆在一起。

### 6.4 设备状态与音量（家长页，Phase 1）

设备状态已经在家长页生效（2026-11-06）：

- 顶部一行：`设备在线 · 12 秒前同步 · 192.168.8.253 · Wi-Fi -72 dBm · 弱`
- 在线判定：设备 15 秒轮询，45 秒内算在线。
- 设备端在 `/api/state.txt` 的查询参数里带 `rssi=`；服务端存 `devices.ip/rssi`。
- 电量：需要确认 1.85C 是否有电池 ADC 采样脚；没有就只显示供电/未知，不显示假百分比。

音量（Phase 1 实现）：

- 家长页新增音量滑块（0–100），存在 `settings.volume`；默认 60。
- 服务端在 `state.txt` 追加 `VOL=`；设备按板型映射到 `audio.setVolume()`（0–21）或 `mp3.volume()`（0–30）。
- 夜间模式可把实际音量压到设定值的 60%，避免睡前过响；具体曲线由实现者定。
- 不做设备端音量手势：长按已用于同步/记录，触摸手势也不适合 5 岁半。

## 七、技术约束与实现方向

### 固件（Arduino / Arduino_GFX）

- 1.85C 使用现有 ST77916 QSPI 驱动、厂商 init 表、`0x3A=0x05`、40MHz、TCA P0/P1 复位；这些是已上机验证的配置，不要回退。
- 新增 `ui_theme` 模块（或同文件函数）：
  - `phase_for_time(hour, minute)` 返回晨/昼/暮/夜；
  - `palette_for_phase(phase)` 返回颜色表；
  - `draw_sun(pose)`、`draw_week_arc(week_cal, weekday)`、`draw_habits_arc(...)`；
  - 背景渐变用逐行 `fillRect` 或少量色带绘制，避免全屏逐像素开销。
- 时间：优先 NTP `getLocalTime`；断网时从 NVS 读取最后一次 phase；RTC 未启用。
- 背光：GPIO5 / GPIO7 用 LEDC PWM；验证亮度曲线，夜间 20% 不刺眼。
- 动画：沿用 `millis()` 状态机；不引入新库；时间/相位逻辑保持纯函数，便于测试。
- 触摸：CST816 需新增坐标读取（寄存器 0x02–0x05），做习惯贴纸/太阳的命中测试；主界面轻点=完成/记录，长按=立即同步；卡片内轻点=翻页，长按=退出。240 板保留现有按键逻辑。
- 音量：新增 `set_volume()`；解析 `VOL=`；1.85 映射到 `audio.setVolume(0–21)`，DevKitC 映射到 `mp3.volume(0–30)`；夜间按设定值 60% 播放。
- 设备状态：`deviceQuery()` 已上报 `rssi=`；服务端存 IP/RSSI 并在家长页显示（已实现）。
- 240（DevKitC）使用同一套主题，按 `SCREEN_W/240` 缩放；圆屏安全区按比例。
- 文字：设备端仍不显示中文；问题的答案/穿衣文字全部走服务器渲染卡片或语音。
- 协议：只做加法。新增 `WEEK_CAL=`、`WEEKDAY=`；保留 `WEEK=`。穿衣若做，优先复用 `rtSeq`；如需图标，再新增 `CLOTH=`（追加在 END 前）。
- 兼容：旧固件继续读 `WEEK=`/`H=`/`MSG=`，不受新字段影响。

### 服务端（server.py / card.py）

- `card.py`：
  - 把 `BG/FG/DIM/GOLD/PINK/GREEN` 换成暖纸配色；
  - 问题卡和字卡共用同一套纸色；
  - 页码点改成薄荷/暖灰；
  - 240/360 两尺寸都验证；不改变 `sections()` 和页数。
- `server.py`：
  - 新增本周日历计算 `week_cal()`（周一到周日，按当前启用习惯数）和 `weekday()`；
  - `state_as_text` 追加 `WEEK_CAL=`、`WEEKDAY=`、`VOL=`；
  - 家长页：顶部设备状态（已实现），「更多」里加音量滑块；

## 十一、已决策 / 留给实现者的决定

### 已决策（2026-11-06）

1. **本期只做 Phase 1**：主界面 + 卡片 + 周点 + 家长页设备状态/音量。穿衣和名字推迟到 Phase 2。
2. **1.85C 直接点**：轻点某个习惯贴纸完成那一件；轻点小豆豆记录问题/留言；长按主界面立即同步；卡片内轻点翻页、长按退出。不做选中环。
3. **周点按当前启用习惯数**：不做每日习惯快照。已知副作用：中途加习惯后，过去完成的日子可能变灰。接受这个取舍，以后变成实际问题再升级真实历史。
4. **冷启动无时间**：先夜间深色 + 20% 亮度，NTP 成功后切到当前时段。
5. **今天全部完成**：保持珊瑚外圈和“今天”尺寸，填充改薄荷，加一个小星星/勾。
6. **名字/穿衣**：不在本期；名字默认只做语音、不做常驻徽章；穿衣留在 Phase 2。
7. **时段边界**：默认 06:30 / 08:30 / 17:00 / 20:00；家长可调不在本期。
8. **家长页旧视图**：旧的“最近 7 天”保留在「更多」里，不占首屏。

### 实现者的决定

- 夜间亮度先用 20%；在 1.85C 上验证 PWM 曲线；如果 PWM 不稳定，退回夜间深色配色 + 最低可行亮度。
- 3/4 件习惯的弧线间距和图标大小在 1.85C 真机上定；2 件的 ±16° 是已确认基线。
- 夜间卡片先不做深色版：暖纸卡 + 设备压暗；如果 20% 下不可读/太亮，再单独评估夜间卡。
- 硬件验收：1.85C 上机验证显示/触摸/网络/卡片/PWM/弧线；DevKitC 与 240 布局本期只保证编译通过，除非手上有第二块板。
- Phase 1 顺带更新 `docs/board-porting.md`：1.85C 已在 2026-11-06 上机验证（I2C 11/10、TCA P0/P1 复位、厂商 ST77916 init、COLMOD 0x05、40MHz）；旧文档的“未上机”描述过时。
